手元の ePub をブラウザで読めるようにし, 同じ本を AI エージェントからも引けるようにしました.
1 つのサービスが, ブラウザで読むためのビューワーと, エージェントから書籍を引くための **MCP**（Model Context Protocol）サーバを兼ねています.
どちらも同じバックエンドと SQLite を使っています.
バックエンドは Haskell, 画面は Elm です.
NixOS のモジュールで設定し, ホスト上でサービスとして動かしています.

ePub を選んだのは, ZIP 内の書誌情報や XHTML の本文を取り出して扱いやすかったからです.
取り出した本文を, ブラウザでの表示とエージェントへの提供に共通で使っています.

## ePub の中身

ePub は, 本文や書誌情報などを ZIP にまとめた形式です.
`mimetype` と `META-INF/container.xml` には決まった名前と配置があります.
仕様は W3C の epub-specs リポジトリで管理されています.

[![w3c/epub-specs のリポジトリカード](https://opengraph.githubassets.com/492d043098a85b49da36a6c9251e82ace1903a9dc0e741f769e6538f3866f04b/w3c/epub-specs)](https://github.com/w3c/epub-specs)

たとえば, 次のような構成です.

```
book.epub
├── mimetype
├── META-INF/
│   └── container.xml
└── OEBPS/
    ├── content.opf
    ├── nav.xhtml
    ├── chapter1.xhtml
    ├── chapter2.xhtml
    ├── style.css
    └── images/
        └── cover.jpg
```

`mimetype` は, この ZIP が ePub であることを表します.
`META-INF/container.xml` が, パッケージ文書（OPF）の場所を指します.

OPF には, 書誌情報, `manifest`, `spine` が入っています.
`manifest` は, 本文の XHTML, CSS, 画像, フォントの一覧です.
`spine` は, 本文を読む順を決めます.
目次は, EPUB 3 ではナビゲーション文書に, EPUB 2 では NCX に書かれます.

本文が XHTML の本では, マークアップからテキストを取り出せます.
このサービスでは, pandoc で本文を抽出しています.
CSS と画像も ZIP の中にあるので, 表紙や図はそのまま取り出せます.

## ブラウザで読む

ビューワーでは, 書籍の一覧, 書籍の詳細, 章の本文を見たり, 検索したりできます.
ブラウザから ePub を登録することもできます.
原本の ePub も SQLite に入れているので, 一覧の表紙も本文中の画像も, そこから取り出して表示します.
本文は, ePub から取り出したテキストを HTML にして表示します.
章を選び, 前後の章に移りながら読めます.
書籍の詳細では, 取り込まれた章の一覧を確認できます.

検索は, 登録したすべての本の本文が対象です.
検索語を入力すると, 該当する箇所の抜粋と, 書籍名, 章が表示され, 結果からその章を開けます.
開いている本だけに絞る検索には対応していません.

一覧と検索結果を切り替えるとページの高さが変わり, スクロールバーが出たり消えたりします.
`scrollbar-gutter: stable` を指定し, スクロールバーの有無で中央寄せのページが横にずれないようにしています.
表紙のない本では, 表紙と同じ大きさのプレースホルダーを置き, 題名の位置が本ごとにずれないようにしています.

## エージェントから引く

MCP のサーバは, 本の本文を検索して, 必要な箇所をエージェントに渡します.
サービス側では回答を生成せず, 根拠になる箇所と出典を返します.
返された情報は, 別のモデルやエージェントでも利用できます.

| 機能 | 返すもの |
|---|---|
| 書籍一覧の取得 | 書籍の一覧 |
| 書誌情報の取得 | 1 冊分の書誌情報 |
| 本文の検索 | 該当する箇所の抜粋と, 書籍名, 章 |
| 前後の本文の取得 | 検索した箇所の前後の本文 |

エージェントは本文を検索して候補を探し, 必要に応じて前後の本文を確認できます.
「〜について書かれた箇所を引用して」といった依頼に使えます.
検索結果には書籍名と章が付くので, どの本のどの章かを示して引用できます.
前後の本文は検索結果に含めず, 必要なときだけ取れるようにしました.

設計論についてコーディングエージェントと壁打ちするとき, この MCP サーバを通じて書籍の記述を引き, その内容を踏まえて議論できます.
たとえば, 自分の設計が書籍で示されている考え方とどう違うかを, エージェントに質問できます.

エージェントに渡すのは参照のためのツールだけで, 本を登録したり消したりする操作はありません.
本を登録するのはブラウザからです.
参照と管理を分けておくと, エージェントに何を任せるかがはっきりします.

## 参照を確かめる

検索結果には書籍名と章が含まれるので, エージェントは出典を示して回答できます.
その章をビューワーで開けば, 引用が本文と合っているかを人間が確かめられます.
ビューワーは読むための画面であると同時に, エージェントの参照を確認する画面でもあります.

## 同じ本文を 2 つの入口から

ブラウザは HTTP の API を使い, エージェントは MCP のツールを呼びます.
MCP に対応したエージェントなら, ライブラリ専用のクライアントを用意せずに済みます.
入口は違いますが, 同じ SQLite の本文を読みます.
ビューワーと MCP は, 同じバックエンドの検索処理を使っています.
取り込みは 1 回で, ブラウザとエージェントは同じ本を見ます.

![1 つの ePub を, ブラウザとエージェントの 2 つの入口から読む](/images/2026-05-14-epub-library-paths.svg)

いまは, 読みたいときはブラウザ, 調べたいときはエージェントと, 同じ本に 2 つの入口から入れます.
ePub から取り出した本文を, ブラウザでの閲覧とエージェントからの検索の両方に使っています.
