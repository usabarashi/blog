プライベート LAN は, 長いあいだ実質的に 1 つのセグメントでした.
以前のルータでは細かい設定ができず, SSID を分けても内部では同じ LAN になっていたためです.
サーバ, スマートフォン, 家電, 仕事用の端末が同じセグメントに接続し, 同じスイッチとアクセスポイントを共有していました.
いまは UniFi のゲートウェイとアクセスポイントに替え, 用途ごとに 4 つの VLAN に分けています.

## UniFi のゲートウェイとアクセスポイント

UniFi は, ルータ, アクセスポイント, スイッチを 1 つのコントローラから管理する製品群です.
コントローラは, 機器とネットワークの構成をまとめて持つ管理用のソフトウェアです.
ネットワーク, SSID, ファイアウォールポリシー, 機器の登録は, コントローラにあります.
機器ごとの画面を個別に設定するのではなく, コントローラの内容が正になります.

この LAN では, ゲートウェイがルータとコントローラを兼ねています.
コントローラはゲートウェイ上で動くので, 管理用のサーバを別に用意する必要はありません.
WAN と LAN の境界, 既定ゲートウェイ, DHCP, DNS, ファイアウォールはゲートウェイが持ちます.
アクセスポイントはコントローラに登録し, SSID と VLAN の設定をそこから受け取ります.

## ネットワーク基盤をサーバから切り離す

ネットワークの基盤は, サービスを載せている NixOS のホストから切り離すことにしました.
ルータをホストに置くと, 管理と復旧の経路が同じ障害領域に入るためです.
サーバの電源は, ネットワーク越しに操作しています.
ホストを更新したり作り直したりするあいだ, セグメントをまたぐ通信が止まり, その経路で触っている電源の管理も止まります.
復旧のための経路を, 復旧したい相手と同じホストに置くことになります.

ルータの OS は, MikroTik の RouterOS も候補でした.
専用の機器で動かせば, この切り離しはできます.
それでも UniFi を選んだのは, 機器と設定を 1 つのコントローラでまとめて扱えるからです.
ゲートウェイとアクセスポイントは専用の機器で, 設定はコントローラに残ります.
ホストを止めても, ゲートウェイが担う通信はそのまま動きます.
理由はもう 1 つあります.
OSS の Terraform プロバイダがあることです.
設定をコードで管理できます.

## 分けた理由

セグメントを分けても, 帯域は増えません.
分けたのは, 同じ LAN に置くと信頼度の異なる端末が直接通信できるためです.
家電は, ファームウェアが更新されないことが多く, スマートフォンのアプリとクラウドのアカウントで設定され, 何をしているかを監査できません.
仕事用の端末は, 雇用側が MDM や EDR で管理していて, 遠隔からの調査や消去ができます.
同じセグメントに置くと, そのどれかが侵害されたときに, 他の端末とのあいだにネットワークの境界がありません.

2 つ目の理由は, ポリシーの適用点を分けることです.
クライアントの DHCP のアドレスプールとブロードキャストドメインを, サーバのセグメントから分けました.
ファイアウォールのルールも, セグメント単位で書けます.

## セグメントの割り当て

| セグメント | サブネット | 用途 |
|---|---|---|
| サーバ | `<SUBNET_SERVERS>` | サービスの置き場 |
| クライアント | `<SUBNET_CLIENTS>` | 私用の端末. スマートフォン, テレビ |
| 家電 | `<SUBNET_IOT>` | 他のセグメントへの新規接続を遮断 |
| 仕事用 | `<SUBNET_WORK>` | 他のセグメントと双方向に遮断 |

表に書いた境界は, IPv4 で意図しているものです.
家電へは, 家の端末から始めた接続が通り, 応答も返ります.
VPN で使うセグメントは, この分離の対象外です.
表とコードの山括弧の値は, 置き換え用のプレースホルダーです.

## DHCP と DNS

クライアント, 家電, 仕事用のセグメントでは, DHCP と DNS をゲートウェイが答えます.

```hcl
resource "unifi_network" "iot" {
  name    = "IoT"
  purpose = "corporate"
  vlan    = <VLAN_IOT>
  subnet  = "<SUBNET_IOT>"

  dhcp_server = {
    enabled     = true
    start       = "<POOL_START>"
    stop        = "<POOL_END>"
    dns_enabled = true
    dns_servers = ["<IOT_GATEWAY>"]
  }
}
```

DHCP が配る DNS サーバは, そのセグメントのゲートウェイのアドレスです.
端末に外部のリゾルバを固定すると, その端末はこの経路を使いません.

名前はサイト全体で解決されます.
コントローラの DNS レコードにはネットワークのスコープがなく, ゲートウェイの DNS に問い合わせる端末には, どの VLAN でも同じ答えを返します.
セグメントごとに名前を管理していますが, DNS の公開範囲は分かれません.
境界はファイアウォールです.
家電のセグメントには, 名前を用意していません.

## Terraform で管理する

ここまでの構成は, UniFi の Terraform プロバイダで管理しています.
VLAN, SSID, ファイアウォールポリシーは, コードで宣言します.

[![filipowm/terraform-provider-unifi のリポジトリカード](https://opengraph.githubassets.com/ca1acd53212901604641fcd0fb4e022f52c1c322f1ad172b5fdb0c27503acefc/filipowm/terraform-provider-unifi)](https://github.com/filipowm/terraform-provider-unifi)

UniFi Network とプロバイダ v0.59.0 で試した範囲では, Terraform では表現しきれず, 手作業か別の操作が要る設定もあります.

- **SSID のパスフレーズ**: 書き込み専用の `passphrase_wo` なので state に入りません.
  ただし `_wo_version` がなく, 変数だけを変えても差分が出ません.
  `-replace` で SSID を作り直して反映します.
  このとき無線の接続は一時的に切れます.
- **ポリシーの並び順**: ポリシーは末尾に追加され, `index` は読み取り専用です.
  例外の許可ポリシーは, 管理画面で遮断ポリシーより前に移動します.
- **ファイアウォールのゾーンの割り当て**: ネットワークは `firewall_zone_id` でゾーンに属し, その割り当てはコントローラが持ちます.
  apply のあとに, state とコントローラの割り当てが意図したゾーンになっているか, ポリシーの送信元と宛先のゾーンと対応しているかを確かめます.
  別のゾーンに落ちると, 意図した通信にルールが適用されなくても, エラーや差分には現れないことがあります.
- **DHCP のゲートウェイアドレス**: プロバイダは `gateway_enabled` だけを持ち, アドレス (`dhcpd_gateway`) を送りません.
  フラグを立てると `GatewayIpNotInSubnet` で作成に失敗したため, 未設定のままコントローラに任せています.
- **DNS のフィルタリング**: ゲートウェイの DNS で広告をブロックし, セーフサーチに制限できます.
  これらはプロバイダが表現しないため, コントローラの画面で設定します.
  DHCP がゲートウェイを DNS に指定しているので, その DNS を使う端末に効きます.
  端末が DoH や VPN を使うと, このフィルタは迂回されます.
- **アクセスポイントの固定アドレス**: `config_network` への書き込みが `InvalidPayload` で拒否されたため, 管理画面で設定します.

## エージェントを LAN に置く

コントローラは LAN の中にしかありません.
HCP Terraform のホストされた実行環境はインターネット側にあり, プライベートアドレスには届きません.
そのため, HCP Terraform のワークスペースは, LAN の中のホストで動くセルフホストのエージェント (tfc-agent) で apply します.
エージェントはサーバのセグメントに置き, コントローラと同じ LAN から接続します.

エージェントのホストが止まっているあいだは apply できません.
コントローラの設定は残るので, ゲートウェイが担う通信はそのまま動きます.

## おわりに

ネットワークは専門ではなく, 分からないところがまだ多くあります.
いまは, IaC で少しずつ作っては直し, 盆栽のように育てながら学んでいます.
この構成も, これから変わっていきます.
